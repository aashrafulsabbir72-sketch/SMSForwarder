# Central backend setup

The APK's existing SMS forwarding path is preserved. Telegram command polling is centralized in the Termux backend.

## One-time backend provisioning

```bash
cd ~/SMSForwarder2/backend
./provision.sh
```

The script asks for the Telegram bot token and authorized chat ID, validates the token, generates a random backend key, and stores them in `backend/.env` with mode 600. The Telegram bot token stays on Termux.

## Connect the APK

Open the APK and tap **TELEGRAM CONTROL SETUP**. Enter the exact backend URL reachable by the phone and the backend key generated by `provision.sh`. No APK rebuild is required when the backend key changes.

For Termux running on the same phone, the usual local URL is `http://127.0.0.1:8899`. For a remote/FRP connection, use the exact URL configured for that environment rather than assuming a fixed public IP.

## Run backend

```bash
cd ~/SMSForwarder2/backend
./start.sh
```

## Control flow

`Telegram -> Termux backend -> device command queue -> Android app -> acknowledgement -> Telegram`

The Telegram bot exposes an allowlisted set of app actions only. It does not execute arbitrary shell/code commands on the phone.

## Device events
The APK may send authenticated informational/test/transaction events to `/api/v1/event`. Common authentication-code patterns are redacted on-device before transmission.
